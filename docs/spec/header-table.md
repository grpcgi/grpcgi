# grpcgi frozen header table

Generated by `docs/spec/tools/header_table.py`. Do not edit by hand.

This registry assigns a protobuf field number to each well-known HTTP field
name in `RequestHead` and `ResponseHead`. It is frozen for the life of the
major version: numbers are never added, removed, or renumbered, because an
older receiver cannot recover a header name from an unknown field number and
would silently drop the header. Any name not listed here travels in the
overflow `headers` list. See `schema.md` for the encoding rules.

Every entry is `repeated bytes` unless marked typed. Values for a listed name
MUST all be carried in the dedicated field; a receiver treats the same name
appearing in `headers` as a protocol error.

## Names that never appear in a head

Pseudo-headers are carried by typed fields, `host` is folded into `authority`,
and hop-by-hop fields are removed by the edge. A sender MUST NOT emit these in
`headers`; a receiver MUST treat them as a protocol error.

- `:authority`
- `:method`
- `:path`
- `:protocol`
- `:scheme`
- `:status`
- `host`
- `connection`
- `keep-alive`
- `proxy-connection`
- `transfer-encoding`
- `upgrade`
- `http2-settings`
